# Graphs: data layer (Phase 3) and graph UI (Phase 4 of 0.2)

The data layer (storage, packs, store, validation) comes first, the graph UI (canvas, Navigator list, Variables, data binding, mock data) is the last section. Codegen is in `docs/codegen.md`. Formats are owned by `inkwell-spec` (`graph.ts`, `pack.ts`, `pins.ts`); read them there.

## Files and IPC

- A graph is `swfs/<swf>/graphs/<graphId>.json`. `src/main/project/graphFiles.ts` reads and writes it with `stableStringify` (sorted keys, 2-space indent, trailing newline; array order of nodes and edges is data and kept). Unknown keys at every level survive (the Spec schema is loose). A file that fails the schema or whose `id` differs from its file name is reported as a problem and left on disk, never deleted. Graph ids are checked (`isGraphId`) so an id cannot escape the folder. Writes use the same lock as `overlay.json`.
- `loadProject` returns `swfs[name].graphs` and `saveProject` writes them (never deletes graph files).
- One menu-scope graph per SWF (`createGraph` refuses a second); component graphs are created per component. The id is made from the name (`newGraphId`).
- IPC (`InkwellApi`, channels `graphs:*`, `packs:get`): `listGraphs(swf)`, `loadGraph(swf, id)`, `saveGraph(swf, graph)`, `createGraph(swf, name, scope)`, `deleteGraph(swf, id)`, `getPacks()`. All resolve `{ok:true,...}` or `{ok:false,error}`. Main keeps the last saved copy of every graph (like overlays) and validates it.
- **Overlay `scripts`** holds the graph ids attached to a Figma node (`NodeOverlayPatch.scripts`). The renderer owns overlays, so attaching or detaching a graph is `editNode(swfId, nodeId, {scripts})` in the renderer, next to `createGraph` / `deleteGraph`; main never edits the overlay (a later renderer save would overwrite it).

## Targets and orphans

A component-typed input pin (Text, Button, List, Image, Clip) with no wire takes its Figma layer id from `fields[<pin name>]` (our convention; the Spec leaves `fields` open). If the layer is no longer in the SWF's IR the node becomes an **orphan**: it stays in the file with its fields untouched, `graph-target-missing` is an error pinned to the node (carrying the layer id), and `graphOrphans()` lists it. Same rule as overlay entries: never dropped. Relinking is setting the field again. Graphs of orphaned SWFs are not validated.

## Packs (`src/main/packs/`)

`loadPack(dir)` reads `manifest.json` and `nodes/*.json` (the layout of Inkwell-Core-Pack), validated with `PackManifest` / `NodeDef`. A bad node file is a `problem` and is skipped; the rest loads. `loadPacks(dirs)` never throws. Definitions are indexed as `packId/kind@major` (`defIndex`). The bundled core pack folder is `resources/packs/core` (copy of Inkwell-Core-Pack when it lands), overridden by `INKWELL_CORE_PACK`; until it exists the pack set is empty and every pack node validates as unknown. `compatible.tool` is not evaluated yet (see the shortcut in `packs/index.ts`). Nodes of packs that are not installed load as ordinary nodes, are listed as `graph-unknown-node` ("Unknown Pack Node (Data Preserved)") and survive save unchanged.

### Downloaded packs (0.5, `src/main/packs/manager.ts`)

- **Formats** are the Spec's (SPEC-CHANGES W1/W2): `packs.lock` (JSON, `{specVersion, packs: [{id, version, source, sha256}]}`, `parsePacksLock` / `writePacksLock`) and the Packs Index (`PackIndex`, fetched from `raw.githubusercontent.com/Inkwell-UI/Inkwell-Packs-Index/main/index.json`; `INKWELL_PACKS_INDEX` overrides the URL). A release is the asset `pack.zip` on the tag `v<version>` (`packAssetUrl`): never the GitHub API.
- **Cache:** `<project>/packs-cache/<id>@<version>.zip` plus the extracted folder (git-ignored, `PROJECT_GITIGNORE`). A locked pack is loaded only when its cached zip has the lockfile's SHA-256 (`lockedPacks`: `ok`, `missing`, `mismatch`); the session's pack folders are the bundled core pack first, then those (`refreshPacks` on project open and after an install or restore; lint, preview builds, the AS2 view and deploy all read them).
- **Flow:** `resolve` downloads into memory and returns a candidate (repo, version, content hash, node count, CHANGELOG.md); nothing is written until `install(token)` writes the cache and replaces the pack's lock entry. `restore` re-downloads what the cache lacks from each entry's `source`, so a pack removed from the index still resolves; a different hash is refused. `checkUpdates` (only on request) fetches each locked pack's latest release (repo from the index, else from the source URL) and returns newer ones with their changelog. The id `core` cannot be installed (the editor bundles it). An unreadable `packs.lock` is reported and never overwritten; the pre-0.5 placeholder `packs: []` reads as empty. `loadProject`/`saveProject` no longer touch `packs.lock` (the build pipeline re-saves a cached project).
- **Offline:** every network failure is an `{ok:false}` with "Cannot reach GitHub (are you offline?)"; cached packs keep loading and builds never need the network.
- **UI:** Assets > Node packs (`renderer/packs/PacksSection.tsx`): the bundled core pack and the locked packs with their state, Download (restore), Add Pack (index search, or `owner/name` / a GitHub URL; the confirm view shows repo, version, hash, nodes and changelog), Check Updates (changelog first). `reloadPacks()` (`hooks/usePacks.ts`) refreshes the renderer's pack set; a project switch does it too.
- **Tests:** `manager.test.ts` with an injected `fetch` (install, hash mismatch refused, removed-from-index restore, offline, update with changelog, tag/version checks, unreadable lock, unknown node flagged then resolved); `readZip` in `deploy/zip.test.ts`.

Pin resolution (`resolvePins`): `typeFrom: "<field>"` takes the pin type from that field (a pin type name) or from the graph variable whose id is in it; `extra.dynamicOutputs: "<field>"` appends one data output per `{name, type}` of the array field (On Widget Call params), `extra.dynamicInputs` the same for data inputs (Call Widget args; codegen placeholder `{{args}}`). Lint `graph-widget-call` (error): a Call Widget with no On Widget Call of that name in the same graph, with other parameter types, or whose call leads back into its own handler (also through a second handler). Entry nodes are `extra.entry`, editor-only nodes `extra.editorOnly`.

## Store (`src/renderer/state/graphStore.ts`)

One zustand store per graph in React Flow shape (nodes, edges; handle ids `<pin>-in` / `<pin>-out`), with `data` holding the whole file node/edge so unknown keys round-trip (`toFlow` / `toGraph`). History is Knotwork's `createHistory`: typing in a field (`setField`, `rename`) coalesces per word, `beginDrag`/`endDrag` make a drag one entry, selection (`setSelection`) is not recorded. Saves are debounced (300 ms) through `setGraphSaver`; `flushGraphSaves()` before closing. Variables live in the graph file (a `saved` variable, S5, is added to the menu graph with `addVariable({scope: 'saved'})`; `savedTypeError` gives the Spec message for a type other than Bool, Number, String): a menu graph holds menu-scope variables, a component graph component-scope ones (`addVariable` sets the scope from the graph); `visibleVariables` gives a component graph the menu variables plus its own.

**One history per SWF (UX 5.5).** Knotwork's history snapshots a single `nodes` array, so overlay and graphs cannot share one zundo store. `state/swfHistory.ts` keeps the order of edits across the SWF's stores (overlay + every graph): Undo reverts the latest edit of that SWF wherever it happened, Redo replays it, a new edit clears Redo, `useUndo` and the status bar read its counts. Limit: if a store trims its oldest entries (100 each) the ordering list can hold a stale key; it is skipped.

## Validation (single source)

`src/shared/graphValidate.ts` `validateGraph(graph, {defs, layers?, siblings?})` returns Knotwork `Issue`s pinned to graph node ids. Codes: `graph-type-mismatch` (Spec `pinCompat`; coercions pass), `graph-required-pin` (non-Exec input without default, wire or target), `graph-dangling-exec` (warning: exec node no event reaches), `graph-exec-cycle`, `graph-target-missing`, `graph-unknown-node`, `graph-duplicate-handler` (same entry kind + name + target, across the SWF's graphs), `graph-bad-wire`. Everything is an error except dangling exec (a warning, an error in Strict Mode).

Main runs it (`session.ts` `refreshGraphLint`) on open, on every graph save/create/delete and after each sync status/layer change, and publishes `SyncUiState.graphLint` (merged into the Lint dock by `useDockRows`, counted in `lintCount`) and `DeploySwf.graphLint` (export gate, Strict Mode). The renderer's live node badges use `createGraphValidation` (Knotwork `createValidation` around the same function), so there is one rule set, run in two places for two readers (dock/gate from saved graphs, canvas from the open one).

## Graph UI (Phase 4)

Debugging (AS2 split, Play, trace, pin values, Lint row opens the graph node): `docs/debugging.md`. Panels: `GraphPanel` (zone 4), the Navigator's GRAPHS section (`graph/GraphsList.tsx`), `VariablesPanel`, `DataBindingPanel`, `MockDataPanel`, and the graph-node branch of the Inspector (`graph/GraphNodeInspector.tsx`). Reference for the panels: `docs/ui-panels.md`.

### Which graph is open (`state/graphDocs.ts`)

`useGraphDocs` keeps, per SWF, the graph ids (file order) and the open graph; `loadSwfGraphs` loads every graph of the SWF once (`listGraphs` + `loadGraph`) into `graphStore`s (`useSwfGraphs()` does it for the active SWF). `bridge.ts` wires `setGraphSaver` to `saveGraph`.
- **[+ Graph]** (`addGraph`): the menu graph when the SWF has none, otherwise a component graph. `createGraph`, then the new id is appended to the overlay `scripts` of the SWF's root frame (menu graph) or of the selected layer (component graph; the root frame when nothing is selected) with `editNode`, so it joins the SWF's undo history. `removeGraph`: `deleteGraph`, then the id is removed from every layer's `scripts`, the store and its history entries are dropped (`dropGraphStore`, `unregisterHistory`: a late debounced save cannot bring the file back). Create and delete hit the disk at once and are not themselves undoable. `renameGraph` is a normal undoable edit of the graph name.
- **One selection model:** the selection also names the graph of the selected node (`SelectionState.graph`), so a Lint row or a trace line can open it. Selecting a component opens its graph (`model/graphNav.ts` `graphForComponent`, applied in `bridge.ts`: the first existing graph of the layer's `scripts`; the open one is kept when it already is one of them). Clicking a graph node calls `selectGraphNode(node, target)`, where `target` is the layer of the node's first component pin (`nodeTarget`), so the Navigator follows.

### Canvas (`graph/GraphCanvas.tsx`, `graph/NodeView.tsx`)

React Flow with Knotwork's `NAVIGATION_PROPS` (`onlyRenderVisibleElements`: off-screen nodes are not mounted), `HaloEdge`, `createClipboard` (Ctrl+C / V / D, one undo entry per paste), `FindBar` (Ctrl+F, title or field value), `SpawnMenu` (Space, or a wire dropped on empty canvas) and `useWheelNavigation`. One React Flow node type (`NODE_TYPE`); the kind is `data.kind`, so an unknown pack kind renders through the same component. Edits go through the store's actions only: a drag is `beginDrag`/`endDrag` (one entry), typing coalesces per word, `deleteSelection` and `addNode(.., wire)` are one update each. A node's own wiring and issues reach it as primitives (`useStore` selectors over Knotwork's `incoming`/`outgoing` indexes, `createGraphValidation` `byNode`/`pinsByNode`), so a node re-renders only for its own changes and nothing scans the node or edge arrays per node.

- **Pins** (`model/graphModel.ts` `PIN_STYLE`, `graph/graph.css`): shape AND colour per type (Exec triangle, Bool diamond, Number circle, String square, Array hexagon, Object octagon, components a hollow frame in their own colour; component pins also print their type), colours are `--pin-*` in `theme.css`. Exec wires are thick and white, data wires thin and in the colour of the type they carry. Tooltips give `name: type`.
- **Connection rules** (`connectionRule`): Knotwork's `composeRules` over: both pins exist (an unknown pack node has none), pins match (Exec only to Exec; data by the Spec's `pinCompat`, `same` and `coerce` pass), `noSelfLink`, an Exec output and any data input take one wire (an Exec input takes many), no Exec loop. Knotwork's `pinsMatch`/`pinUsedOnce`/`noLoop` read the pin KIND from the handle id (`Number-out`), ours are pin names (`then-out`), so those three are written here against the pack's pin types. A generic `pinType(handle)` option in Knotwork would remove the copy (not done; change Knotwork, not here).
- **Spawn menu**: `spawnDefs` turns every pack node into a Knotwork `NodeDef` (pin id `<PinType>:<pin name>`), categories ordered Events, Flow, Variables, Logic, Data, Components, List, Game, Animation, Debug, Editor-only. A wire dropped on a pin offers the nodes with a pin of the same type (Knotwork matches by equality, so a Number output does not offer String inputs even though that wire is allowed), each tried against `connectionRule`; the picked node is created at the cursor and wired in the same update.
- **Inline fields** (`fieldRows`): the pack's fields (enum, string, number, bool; `variable` is a picker of the graph's variables; `params` is the On Widget Call parameter editor: name, type String/Number/Bool, add/remove, names forced to identifiers) and one editor per UNWIRED data input pin, stored in `fields[<pin name>]` (a wired pin shows none). An unwired component-typed pin (Text, Button, List, Image, Clip) shows a layer picker listing the SWF's layers by instance name (overlay name, else layer name) and stores the Figma layer id in `fields[<pin>]`; Text pins list text layers, Image pins image layers. A stored id that is not a layer any more stays selectable as "Missing layer <id>" (orphan rule above). The same editors are shown by the Inspector for the selected graph node.
- **Editor-only nodes**: Reroute (a small String-typed passthrough; `typeFrom: "connection"` is not evaluated by validation or codegen, so a Reroute only carries what a String pin accepts), Comment (text box), Group (a labelled frame, size in `fields.w`/`fields.h`, drawn behind the other nodes; it does not own nodes).
- **Issues**: `createGraphValidation` (the shared `validateGraph`) feeds a badge (icon plus message tooltip, border colour) on each node and a wavy underline on the pin with the issue; the Lint dock shows the saved graph's issues from main. An unknown pack node shows a striped header "Unknown Pack Node (Data Preserved)", its kind, and handles for the pins its wires use; its fields stay untouched.
- **Header**: breadcrumb `GRAPH: <swf> > <graph> > <layer it hangs on> > <selected node>` (the SWF and the layer are links) and the event jump list (every entry node; selects and centres it).
- **AS2 split, live pin values**: Phase 6, `docs/debugging.md`. A selected node highlights its lines in the AS2 view; an output pin shows the last value the Ruffle preview traced (small badge).
- **Tidy Layout** (`model/graphLayout.ts`, header button): layers by longest path along the wires, rows ordered by their sources' average row, anchored at the top-left of the old bounds; one undo entry, then the view fits. **Not built**: node collapse. Variables used by a component graph's Get/Set Variable nodes must be the graph's own (validation and codegen resolve `g.variables` only; `visibleVariables` also lists the menu graph's for the Variables panel).

### Variables (`VariablesPanel`)

Add (name, type Bool/Number/String/Array/Object, scope menu | component), rename, retype, default, delete. A menu variable is added to the SWF's menu graph, a component variable to the open component graph (`model/variables.ts` `variableTarget`; the button says why when neither exists). The id is made from the name, unique across the SWF's graphs (`newVariableId`); nodes refer to the id, so renaming is safe. Edits are graph-store edits: SWF history, saved with the graph file.

### Data binding and mock data

- **Binding** (`DataBindingPanel`, `shared/graphBinding.ts`): the selected layer's text (text layers only), visible, alpha and tint can each be bound to a graph variable (the menu graph's menu variables plus the variables of the layer's own graphs) or a mock data field. The Spec types the overlay entry's `dataBinding` as ONE string, so the bindings are written as `;`-separated `<property>=<source>:<name>`, e.g. `text=var:score;alpha=mock:hp` (`var:` = a graph variable id, `mock:` = a mock data key). Parts the parser does not understand are kept. Written with `editNode(swf, layer, {dataBinding})`: one SWF history entry. A bound source that no longer exists, or whose type is not the one the property wants, shows a warning (not blocked: codegen would coerce). Codegen applies them (`docs/debugging.md`, Data binding codegen): a bound variable on init and after every Set Variable, `mock:` fields in the Ruffle preview. Proposal for the Spec: a structured `dataBinding` object (the string keeps us inside the current schema).
- **Mock data** (`MockDataPanel`): a key/value list per SWF (key, type String/Number/Bool, value) stored in the SWF's overlay document under the top-level `mockData` object (`swfs/<name>/overlay.json`; the overlay schema keeps unknown keys). It joins the SWF's undo history (`editOverlay`), is never shipped, and is delivered to the running Ruffle preview (`docs/debugging.md`, Mock data) and never rebuilds the SWF. Text boxes commit on blur or Enter so typing is not one entry per key. Presets and a JSON view are not built.

### Runtime lint (Phase 5)

`runtime-required` (warning, HUD widget graphs only) uses the node definition's `requiresRuntime` (`needsRuntime`); the title lists of the Spec are no longer consulted, so a pack must set the flag. A `saved` variable in a HUD widget is also `runtime-required`; `saved-variable-invalid` (error) covers a saved variable outside the menu graph of a custom menu, a non-saved type, a name used twice in the SWF and a name outside 1 to 64 bytes.
