# HUD widget output (`src/main/widget`)

Milestone 0.1 items 14-16. `compileWidget(ir, { modId, widgetName?, buildDir, ffdec, papyrusExe? })` turns an IR whose `target.kind` is `hudWidget` into an in-memory mod folder (`{ files, lint, timings }`); `writeModFolder(dir, files)` writes it.

> A mod that also has a custom menu gets a second, separate plugin `<modId>_RuntimeCheck.esp` (no master, no SkyUI) with its own quest and script; it never touches this widget plugin (`docs/menus.md`, Runtime check).

## What is generated

```
Interface/exported/widgets/<modId>/<widgetName>.swf   the widget SWF
Scripts/<modId>_<widgetName>.pex                      compiled widget script
Scripts/<modId>_<widgetName>Instance.pex              compiled empty Instance script
Source/Scripts/<modId>_<widgetName>.psc               generated sources, shipped for readability
Source/Scripts/<modId>_<widgetName>Instance.psc
<modId>.esp                                           ESL-flagged plugin, master SkyUI_SE.esp
```

- **Widget frame.** The first frame child of the root frame is the widget (a root with no frame child is the widget itself). Its children become the content of the root clip; its position, anchor and opacity go to the Papyrus script, not into the SWF. Other top-level layers are skipped with warning `widget-extra-content`.
- **SWF** (`generate(ir, { widget: true })`, same generator as every SWF): the content sits inside a sprite placed on the main timeline with instance name `widget`. Text still uses imported alias fonts plus outlines (one `ImportAssets2` per font). Generated AS2 `mods.<modId>.<Swf>Widget.install(widget)` (exported class in `__Packages`, called from `frame_1/DoAction.as`) gives the clip the SkyUI contract: `setHudMetrics`, `setRootPath`, `setClientInfo`, `setModes`, `onModeChange`, `setHAnchor`, `setVAnchor`, `setPositionX`, `setPositionY`, `setAlpha`. Flash 8 AS2, no `Error` class. The AS2 follows the 0.0 spike (proven in game on SkyUI 5.2.0.0SE and 6.11) but is original code. There is no `setLabel`; a widget without settable texts is static (see Popup below).
- **Placement override.** The widget frame's overlay entry may hold `anchor: { h: left|center|right, v: top|center|bottom, x, y }` (Inspector: "Screen position (SkyUI)" plus two margins, shown only on a `hudWidget`'s widget frame, replacing the disabled "Anchor override" row there). It replaces the Figma position: the anchor point is the anchored screen edge moved inward by `x`/`y` design px (for `center`, right/down), times 2/3. Example: top right with 24/24 gives `HAnchor right`, `X = 1280 - 16 = 1264`, `Y = 16`.
- **How SkyUI reads X/Y** (SkyUI 5.2 `WidgetBase.as` / `WidgetLoader.as`, read from the user's install, not copied): `X`/`Y` are the *anchored* point, not the left/top edge. `updateAnchor` shifts the holder (the widget's parent) by `-width` for `right`, `-width/2` for `center`, `-height` / `-height/2` for `bottom` / `center`, and the clip goes to `Lerp(-hMin, hMax, 0, 1280, X)` (and the same with `vMin`/`vMax`/720), where `hMin`/`vMin` are the safe-rect origin and the widget container sits at that origin, so on screen the anchored edge lands exactly on `X`/`Y`. The generated contract does the same (`lerp(targetMin, targetMax, sourceMin, sourceMax, v)` in SkyUI's argument order; `_width`/`_height` already include the 2/3 scale).
- **Worked example (the dogfood popup, 411x200 design px, top right, margins 24/24):** `X = 1264`, `Y = 16`; size `274 x 133.33` HUD px. HUD box: left 990, top 16, right 1264, bottom 149.33. On a 1920x1080 screen (x1.5): **left 1485, top 24, right 1896, bottom 224** (24 px from the right and top edges).
- **Fixed bug (2026-10-24):** the contract's lerp had target and source swapped (`c + (d - c) * (v - a) / (b - a)` with SkyUI's argument order), which inverts the safe-rect mapping: every widget landed `2 x` the safe-rect inset right and down. Measured by the owner on the first popup build: card left at 1535 / top at 75 screen px (1023 / 50 HUD) instead of 1485 / 24, with about 25 px cut off at the right; that is an inset of about 16.5 x 17 HUD px (25 screen px). `widget.test.ts` runs the generated AS2 against a simulated SkyUI and reproduces both numbers. The 0.0 spike and the `samples/hud-widget` test (top right) had the same offset but were never measured. Without it the Figma position and constraints are used as before. A malformed `anchor` is reported by `overlayProblems` and ignored by the compiler.
- **Scale.** Design space is 1920x1080, SkyUI's HUD space 1280x720. Both are 16:9, so one factor k = 2/3 applies: the `widget` clip is placed with scale 2/3, the SWF stage is 1280x720, and the Papyrus `X`/`Y` are the design anchor point times 2/3. The anchor point is the frame's left/centre/right (top/centre/bottom) edge from its IR `anchor`; `stretch` and `scale` anchors fall back to left/top.
- **Papyrus.** `<ModId>_<WidgetName>` extends `SKI_WidgetBase`: `OnWidgetInit` sets `WidgetName`, `HAnchor`, `VAnchor`; `GetWidgetSource` returns `<modId>/<widgetName>.swf` (relative to `Interface/exported/widgets/`); `GetWidgetType` returns the script's own name; `OnWidgetReset` calls `Parent.OnWidgetReset()` then sets `X`, `Y`, `Alpha` (percent). `<ModId>_<WidgetName>Instance extends <ModId>_<WidgetName>` is empty. Both names must be ASCII letters and digits (starting with a letter). `Debug.Trace` lines `[Inkwell] <script> OnWidgetInit` / `OnWidgetReset at x,y` go to the Papyrus log.
- **Plugin** (`esp.ts`): a hand-written, ESL-flagged ESP with master `SkyUI_SE.esp` and one start-game-enabled quest `<ModId>_<WidgetName>Quest` (form id `0x01000800`) with the Instance script attached through VMAD. The record layouts are documented at the top of `esp.ts`. Byte-identical to the 0.0 spike plugin, which loaded in game; not checked in xEdit/CK.

## Popup: settable texts, Show/Hide

A text layer whose overlay `role` is `text` is settable from Papyrus (`compileWidget(ir, { overlay })`, `generate(..., { settableTexts })`). Its instance name (overlay `instanceName`, default the sanitized layer name) names the AS2 field and the Papyrus parameter (`title` -> `asTitle`). Settable names must differ ignoring case (error `widget-text-name-clash`, Papyrus is case-insensitive). A widget with at least one settable text becomes a popup:

- **AS2** (same `...Widget` class, after the contract methods; each block tagged with its node id): the clip starts hidden (`_visible = false`, `_alpha = 0`). `setTexts(a0, a1, ...)` sets each field's `text` in layer order (`undefined` -> ""). `show(holdSeconds)` fades in from the current alpha over 0.3 s, holds, fades out; `holdSeconds <= 0` stays until `hide()`; a `show` while visible restarts the hold without a jump. `hide()` fades out from the current alpha. The tween is `onEnterFrame` + `getTimer()` (frame-rate independent) and deletes itself when done; `setAlpha` from SkyUI is multiplied by the fade. At install each settable field gets `autoSize = "none"` (it keeps its Figma box, so a long title cannot push into the body) and `textAutoSize = "shrink"` (verified in game on fixed boxes, SPIKES 9 and 11); the layout class still applies the IR's own `textFit` after it. Alignment and `verticalAlign` stay as designed.
- **Papyrus** (widget script): `SetTexts(String asTitle, String asDescription)`, `Show(String asTitle, String asDescription, Float afHoldSeconds = 4.0)`, `Hide()`, all through `UI.InvokeStringA` / `UI.InvokeFloat` on `"HUD Menu"`, `WidgetRoot + ".setTexts"` etc. Calls made before `Ready` are remembered (`_texts`, `_pendingShow`) and applied in `OnWidgetReset`, which SkyUI runs after every load (each load recreates the SWF hidden; the last texts are re-applied, a pending Show runs once).
- **Test hotkey (off by default):** `Int Property DebugHotkey = <n> Auto`, where `<n>` is the widget frame's overlay `debugHotkey` (an integer DirectInput scan code 1..255, Inspector "Test hotkey (scan code)" under "Screen position"; absent = 0 = off; anything else is reported by `overlayProblems` and compiles as 0). `OnWidgetReset` (every game load) calls `UnregisterForAllKeys()` and, when the property is non-zero, `RegisterForKey(DebugHotkey)` (SKSE). `OnKeyDown` shows the sample texts (`Show("Inkwell test", "...", 4.0)`) unless `Utility.IsInMenuMode()` (console, any menu). Log lines: `[Inkwell] <script> debug hotkey 65` on load, `[Inkwell] <script> debug hotkey: Show` on a press. Keep it unset for a release build. Common codes: F7 = 65, F8 = 66, F9 = 67, F10 = 68, F11 = 87, F12 = 88. Auto property values are stored in the save once the script has run, so a later rebuild with a different default does not change an existing save's value (a new save, or a save from before the property existed, takes the new default).
- **`Function Test() global`** stays for other scripts: it finds the quest with `Game.GetFormFromFile(2048, "<modId>.esp")` (local id 0x800, ESL-flagged plugin) and shows the sample texts. The owner's Skyrim SE has no console command that calls a script function, so it is not a console trigger. From another mod: `(Game.GetFormFromFile(0x800, "AchievementPopup.esp") as AchievementPopup_Popup).Show("Title", "Description", 4.0)` (compile against the shipped `Source/Scripts/*.psc`).
- Stubs: `Game.psc` (`GetFormFromFile`), SKSE key functions in `Form.psc` (`RegisterForKey`, `UnregisterForKey`, `UnregisterForAllKeys`, event `OnKeyDown`), `Utility.IsInMenuMode`; declarations only.

## SkyUI rules this relies on

- Two scripts: the widget, and an empty `...Instance` attached to the quest. SkyUI refuses a script whose name equals `GetWidgetType()`.
- SWF under `Interface/exported/widgets/<mod>/`, root clip named `widget`.
- SkyUI files are never bundled or copied. The stubs in `resources/papyrus-stubs/` are written from scratch (marked `original stub`). `HAnchor`, `VAnchor`, `X`, `Y`, `Alpha` are full properties as in the real `SKI_WidgetBase`, not `auto`: a wrong stub compiles silently into direct field stores that do nothing in game (a test checks this).

## Papyrus compiler (user-pointed)

`papyrusCompiler.ts` runs the user's [russo papyrus-compiler](https://github.com/russo-2025/papyrus-compiler) `papyrus.exe` as a separate process: `papyrus.exe compile -nocache -h resources/papyrus-stubs -i <src> -o <out>`. It is never bundled. Set the full path of `papyrus.exe` in the environment variable **`INKWELL_PAPYRUS`** (for example `$env:INKWELL_PAPYRUS = 'C:\Tools\papyrus-compiler\papyrus.exe'`). Compiler errors come back as lint issues with code `papyrus-compile-failed` (`nodeId` = script name, message `Script.psc:line:col: text`) and no `.pex`. Without the variable `compileWidget` still writes the SWF, `.psc` and plugin and warns `papyrus-skipped`; the script `yarn compile:widget` fails instead, since the widget would not run.

## Commands

- `yarn compile:widget`: compiles `samples/hud-widget` (modId `InkwellWidgetTest`, widget `Hud`, top right, outset from the corner, teal outline and green bar, text `INKWELL WIDGET TEST` in `Everywhere / Medium / 24` and a second line in `Everywhere / Bold / 18`) into `build/widget-test/` (git-ignored) and prints stage timings and lint. Needs Java, FFDec, the wrapper jar and `INKWELL_PAPYRUS`.
- `yarn deploy:widget`: copies `build/widget-test/` into `C:\Modding\MO2\mods\Inkwell Widget Test\` (override with `INKWELL_WIDGET_DEPLOY`). Never writes to the game's `Data` folder.

## Unverified

- The whole popup path (setTexts, the fade, shrink on a previously auto-height field, the SKSE key registration and `IsInMenuMode` filter, the global `Test` and `GetFormFromFile` with an ESL local id, calls before `Ready`) is generated and compiles (FFDec, russo), and the hardcoded popup ran in game (SPIKES 15). The graph-driven version (On Widget Call) ran in game on 2026-10-25: Show and the Nodes widget worked; the tint binding, the fade-out, Hide and `fail=true` were not individually confirmed (see STATUS-0.2.md).
- `Ready` is assumed to stay false until the new SWF has loaded after a game load; a call in that window could be lost.

- The corrected lerp follows SkyUI's own `WidgetBase`; the fix has not been seen in game yet. The safe-rect inset (about 16.5 x 17 HUD px) is inferred from one screenshot. Ultrawide or custom HUD metrics are untested.
- Alpha: `setAlpha` sets the clip's `_alpha`; the Papyrus `Alpha` is the frame opacity times 100.
- Output compiled by russo matches the official compiler by reading only (see the spec's 0.0 notes).

## Graph-driven widgets (0.2)

If the SWF has a graph with On Widget Call entries, the widget's behaviour comes from the graph: the AS2 widget class loses the hardcoded popup API (`setTexts`/`show`/`hide`, fade) and the Papyrus script gets one typed function per entry (`Function Show(String asTitle, Float afHold)`); `Test()` calls the first entry with sample arguments; the debug hotkey does the same when there is one entry, with several **each press runs the next step** (an entry with a Bool parameter gets two steps, False then True; strings `"Inkwell test"`, `"Text 2, ..."`, numbers 4.0), so one key tests every entry (graph file order; ids sort alphabetically, so the popup graph is `main`). Arguments travel as one `String[]` through `UI.InvokeStringA` and the generated clip method converts them back. **A call made before the widget is Ready is remembered (the last one only) and replayed once in `OnWidgetReset`**, like the 0.1 popup; `Ready` is still only assumed to stay false until the SWF loaded (unverified in game). Without such a graph nothing changes. Details: `docs/codegen.md`; samples: `samples/hud-graph` (slice) and `samples/hud-graph-popup` (below).

## The popup as a graph: `samples/hud-graph-popup` (Phase 7)

The 0.1 AchievementPopup behaviour rebuilt from graph nodes; mod id `InkwellGraphPopup`, widget `Hud`, deployed with `yarn deploy:graph-popup` into the MO2 mod `Inkwell Graph Test` (`docs/deploy.md`; test steps in the workspace `TEST-IN-GAME-0.2.md`). The Figma-like IR is hand-made (vector panels, no images, no binaries): frame `Popup` (the widget, top right 24/24, hotkey F7 = 65) holds `card` (panel, `title`, `description`) and `report` (panel, `status`).

- **Graph `main`** (menu scope, on the widget frame). **On Load** hides `card` and `report` (a widget cannot start hidden from the IR: hidden Figma layers are not compiled, and On Load is called at the end of the graph's `init()`). **On Widget Call `Show(title: String, description: String, hold: Number)`**: Set Text x2, Set Alpha 0, Set Visible true, **Fade** 0 to 100 in 0.3 s; its `done` goes to Branch(hold > 0): true = Delay(hold), Fade 100 to 0 in 0.3 s, Set Visible false; false (hold 0) = stays until `Hide()`. **`Hide()`**: Fade 100 to 0, Set Visible false. Papyrus: `Show(String asTitle, String asDescription, Float afHold)`, `Hide()`.
- **Fade** (Core-Pack Components node, `setInterval` + `getTimer()`, no Tween) is the fade mechanism; Delay + Set Alpha steps would need a dozen nodes for 0.3 s.
- **Graph `nodes`** (component scope, on the `report` frame; the checks of the whole milestone): **`Nodes(fail: Bool)`**: Set Visible/Alpha, Set Variable `tint` = 0x3366FF (blue) and `panelAlpha` = 60 (the `report panel` layer has `dataBinding` `tint=var:tint;alpha=var:panelAlpha`, so the panel turns blue at 60% alpha: `Color.setRGB` and `_alpha` binding), Set Variable `lines` = Format("start, fail={0}", fail), Log, Set Text, **Branch(fail)**: true = **Throw** ("deliberate error: Nodes(true)", node id `throw`); false = **For Each** over `[10, 20, 30]` (the array lives in `fields.array` of the node, there is no array editor) appending Format(" [item {0}]", index), Set Text, **Sequence**: then0 = **Do Once** appending " once"; then1 = **Delay** 1 s setting `tint` = 0x33CC66 (the panel turns green), appending " delay" and Set Text. Papyrus: `Nodes(Bool abFail)`. Expected `status` text: `start, fail=false [item 0] [item 1] [item 2]`, one second later `... once delay` (first call only; later calls end in ` delay`); with `fail=true`: stops at `start, fail=true` and logs `[Inkwell] error throw: deliberate error: Nodes(true)`.
- **Graph `extras`** (on the `report` frame): **`Extras()`**, a slice of the more-nodes group in one run: Counter reset/increment/increment, Assert (counter == 2), Add/Multiply/Round/Compare/Select, Split/Join/Substring, Array Push (twice)/Length/Get, Make Object/Get Field, Format, Set Text writing two lines (`math=11 text=a-b-c/Ink pick=big` / `arr=2/y obj=Ada n=2`), a Tween of the report panel's alpha (20 to 100, ease out, 0.3 s) whose `done` appends ` tween`, and a For Each over three items whose body holds a Delay (0.6 s): only the last iteration continues, appending ` retrig:2` once. Graph ids sort alphabetically, so `Extras` is now the first entry: `Test()` and the first F7 press call it.
- **Differences from the 0.1 popup:** Hide fades from full alpha (not from the current alpha); a second `Show` while one is visible restarts the hold (Delay is retriggerable since the more-nodes branch: the pending timer is cancelled; before, the first Delay still fired and hid the card early); `SetTexts` is gone (use `Show`); `Test()` calls `Show("Inkwell test", "Text 2, shown by the InkwellGraphPopup_Hud test", 4.0)`; the F7 hotkey cycles Show, Hide, Nodes(false), Nodes(true).
- **Checked in Ruffle** (`INKWELL_SHOTS_GRAPH=popup`, `src/main/screenshotPopup.ts`, `docs/ui-panels.md`): hidden at start, fade values over time, hold, hide, `Nodes(false)` text, `Nodes(true)` trace line and the widget alive afterwards. **Not run in game.**
