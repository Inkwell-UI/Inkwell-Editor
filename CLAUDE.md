# Inkwell Editor

Electron desktop app that turns Figma designs into Scaleform SWFs for Skyrim SE/AE, with live Figma sync and a visual scripting graph that transpiles to AS2. The full design is in `Inkwell Design Spec.md` (workspace root); read the relevant section before changing behavior. Where this file and the spec disagree, the spec wins; fix this file.

## Commands

Use yarn (not npm).

- `yarn dev`: Electron + Vite dev window.
- `yarn build`: production build to `out/`.
- `yarn test`: Vitest (`src/**/*.test.ts`).
- `yarn typecheck`: `tsc --noEmit`, strict.
- `yarn build:wrapper`: compiles `tools/ffdec-wrapper` to `build/ffdec-wrapper.jar` (git-ignored). Needs a JDK 9+ (portable Temurin 17 in `C:\dev\jdk`, outside the repo, or set `INKWELL_JDK`); `--release 8` so the jar runs on the user's JRE. The FFDec integration test needs `java` on PATH (or `INKWELL_JAVA`) and skips unless FFDec and the jar exist. See `docs/ffdec-wrapper.md`.

- `yarn compile:sample`: compiles `samples/hud-minimal` to `build/sample.swf` (git-ignored) through `src/main/swf` and the wrapper, for in-game testing. Needs the same Java/FFDec/jar as above. See `docs/swf-compiler.md`.
- `yarn compile:images [--deploy]`: the in-game image test (embedded menu `[`, dds menu `]`) into `build/image-test/`; `--deploy` copies it into the MO2 mod `Inkwell Spikes` (`INKWELL_IMAGE_DEPLOY` overrides; never a game Data folder). See `docs/images.md`.
- `yarn compile:widget`: compiles `samples/hud-widget` to the mod folder `build/widget-test/` (SWF, generated Papyrus, .pex, ESP). `INKWELL_PAPYRUS` = path to the user's russo `papyrus.exe` (never bundled; header stubs in `resources/papyrus-stubs/`). `yarn deploy:widget` copies it into the MO2 mod `Inkwell Widget Test`. See `docs/hud-widget.md`.
- Setup Doctor and Deploy (phase 2): settings live in `<userData>/settings.json`; `INKWELL_FFDEC`, `INKWELL_JAVA`, `INKWELL_PAPYRUS`, `INKWELL_SKYRIM`, `INKWELL_MO2_MODS`, `INKWELL_MO2_OVERWRITE`, `INKWELL_FIGMA_MANIFEST` and `INKWELL_CK_SOURCES` override them. `yarn test` runs the doctor against this machine (read-only) and a real widget deploy into a temp folder (needs Java, FFDec and the wrapper jar). Graph UI screenshots: `INKWELL_SHOTS_GRAPH=1`; Phase 6 end-to-end run in the real Ruffle preview: `INKWELL_SHOTS_GRAPH=debug` (`docs/ui-panels.md`, Debug; `docs/debugging.md`). Figma approval screenshots (a fake plugin; prompt, waiting dot, Forget all): `INKWELL_SHOTS_FIGMA=1` (`docs/sync-server.md`). Debug screenshots of both UIs: `INKWELL_SHOTS_SETUP=1 INKWELL_SHOTS_DIR=<dir> INKWELL_SHOTS_PROJECT=<scratch copy of samples/hud-widget> INKWELL_MO2_MODS=<a folder you may overwrite>` plus a separate `--user-data-dir`; it really deploys. Setup Doctor field/browse driver: `INKWELL_DOCTOR_DRIVER=1` (see `docs/setup-doctor.md`, Debug driver). Package Mod and the Deploy menu's Vortex row save the same files as one zip (same planner and export gate; default `<project>/dist/<Name>-<version>.zip`, git-ignored; `INKWELL_SHOTS_PACKAGE_DIR` answers the save dialog in screenshot runs). See `docs/setup-doctor.md` and `docs/deploy.md`.
- Install Skyrim fonts for Figma (Settings > Fonts for Figma, opt-in): `src/main/fonts` extracts every font of the game's `fonts_en.swf` except Consolas with FFDec, renames them (Everywhere Light/Medium/Bold, one family per other face, CreationClub Regular/Bold) and installs them per user (HKCU + `%LOCALAPPDATA%\Microsoft\Windows\Fonts`) with a manifest; "Install missing fonts" appends faces added later. Status shows each font's glyph count; the lint `font-missing-glyph` uses the font's cmap. Tests never touch the real registry or font folder; manual runs use `INKWELL_FONTS_SANDBOX=<dir>` (screenshots: `INKWELL_SHOTS_FONTS=1`). See `docs/font-install.md`.
- `yarn dev` also starts the Figma sync server (127.0.0.1:8787-8790; the plugin connects by approval, no token: the window asks "A Figma plugin wants to connect: Allow?"). Env: `INKWELL_FFDEC`, `INKWELL_JAVA`, `INKWELL_PROJECT`. See `docs/sync-server.md` for the manual test with the Figma plugin. Each sync also keeps `figma/snapshot.json` (provenance and a hash tree root per SWF; builds use `ir.json` + `assets/`, so a project builds offline): `docs/sync-server.md`, Figma snapshot.
- Custom menus (milestone 0.3): `swfs/<name>/menu.json`, the Menu settings panel, generated menu JSON and default INI, the AS2 menu glue and the Ruffle mock runtime are in `docs/menus.md`. Slice sample `samples/menu-slice`; Ruffle/UI run: `INKWELL_SHOTS_MENU=1` (+ `INKWELL_SHOTS_DIR`, `INKWELL_SHOTS_PROJECT=<scratch copy>`, optional `INKWELL_MO2_MODS=<scratch folder>`), see `docs/menus.md`.
- `yarn deploy:menu-nodes` deploys `samples/menu-nodes` (list, saved counter, mod event, Get Setting, Get Input Device, Play Sound) like `deploy:menu-slice` (shared `scripts/menuDeploy.ts`) into `C:\Modding\MO2\mods\Inkwell Menu Nodes Test` with the runtime DLL. Ruffle run: `INKWELL_SHOTS_MENU=nodes` (`docs/menus.md`). Both scripts take `--flat` (slice only: the O2 fallback layout), `--dev` (a Dev deploy: dev SWF, `Inkwell.ini` with DevMode/Token/Port, and the token is stored in the user settings `%APPDATA%\inkwell-editor\settings.json` under `devLinks` of the sample project, so the editor finds it), `--to <...\mods\name>` and `--dll`. The runtime-check ESP is built only when `INKWELL_PAPYRUS` is set; unset it for a deploy without the ESP. The five test folders for the owner and which one to enable: `TEST-IN-GAME-0.3.md` (workspace root).
- Dev mode (0.3 Phase 6b, `docs/dev-mode.md`): the game connection is a `ws` client in the MAIN process (`src/main/runtime/`: `client.ts`, pure `protocol.ts`, `devIni.ts`, `token.ts`; a renderer WebSocket cannot be used: the runtime refuses any Origin header), the Game dot, Trace & Watch `Game (Dev Mode)` source, game pin badges, the Deploy menu's Dev deploy toggle (Inkwell.ini with token, dev SWF with `bridge.pin`/`watch`/`dumpVariables`, hot reload after deploy). Tests use the mock runtime `src/main/runtime/mockRuntime.testutil.ts`; screenshots `INKWELL_SHOTS_DEV=1` (set `INKWELL_MO2_MODS` to a scratch folder for the real Dev deploy). Nothing ran against the real game.
- `yarn deploy:graph-popup` deploys `samples/hud-graph-popup` through the editor's deploy path (`prepareDeploy`, export gate, `commitDeploy`) into the MO2 mod folder of its `project.json` (`Inkwell Graph Test`; `INKWELL_GRAPH_DEPLOY` overrides, it must end in `\mods\<name>`), needs Java, FFDec, the wrapper jar and `INKWELL_PAPYRUS`. Popup/nodes Ruffle run: `INKWELL_SHOTS_GRAPH=popup` (`docs/hud-widget.md`).
- `yarn sync:core-pack` copies `../Inkwell-Core-Pack` (manifest, nodes, templates) into `resources/packs/core`, the pack the editor loads by default. Run it after changing the Core-Pack; commit the copy. The bundled pack has 116 nodes (core pack 0.4.0; the integration test compiles the 113 that have a template).
- Spec package: `@inkwell-ui/spec` is `link:../Inkwell-Spec` (a link to the sibling checkout, not a copy; specVersion 6, Figma protocol 5, runtime protocol 1). After changing the Spec, run `yarn build` in `Inkwell-Spec`; nothing needs reinstalling here. The sibling checkout must exist next to this repo.

## Stack

Electron, React, React Flow, Knotwork (`@nicklaj/knotwork`, pinned to a GitHub tag), Zustand + zundo, Zod, Vite, Vitest. Shared formats come from `inkwell-spec`.

## Rules that are easy to break

- **One SWF per top-level Figma frame** (`swfs/<name>/`, `build/<name>.swf`); one project = one mod = several SWFs. Loose top-level layers are linted `unreachable-node`; swfs of deleted frames are orphaned, never deleted.
- **Figma owns visuals.** Never edit the visual IR in the editor. Behavior (scripts, roles, anchoring overrides, bindings, instance names, focus) lives only in the overlay, keyed by Figma node ID.
- **Shared formats are defined in inkwell-spec.** Never define or change the IR, sync protocol, debug protocol, menu JSON/INI or pack manifest here; change the spec first, then consume the new version.
- **Never drop unknown data:** IR `extra`, nodes from missing packs, unknown contract entries all survive load and save.
- **One validation source:** issues are computed once, pinned to graph nodes and Figma node IDs; components read them, never recompute.
- **Graphs** (`swfs/<name>/graphs/<id>.json`): validated by `src/shared/graphValidate.ts` only (main for the Lint dock and export gate, renderer through Knotwork `createValidation` for badges); a node targeting a deleted Figma layer is an orphan, never dropped; the SWF's one undo history orders overlay and graph edits (`state/swfHistory.ts`). See `docs/graphs.md`.
- **Graph UI edits only through store actions** (`graphStore`, `editNode`/`editOverlay`): a drag is one entry, a spawn with its wire is one entry, attaching or deleting a graph edits the overlay `scripts` in the renderer. Data bindings are one `dataBinding` string per layer (`shared/graphBinding.ts`) and mock data lives in the overlay document's `mockData`; both join the SWF's undo history. See `docs/graphs.md`, Graph UI.
- **Generic graph code belongs in Knotwork.** If a change isn't Inkwell-specific (indexes, rules, undo, spawn menu, clipboard, navigation), make it in the Knotwork repo and bump the pinned tag.
- **No per-node scans** of node or edge arrays; use Knotwork's indexes. Only visible graph nodes are mounted.
- **Custom menu = target `customMenu`, not a project kind.** `swfs/<name>/menu.json` is the Spec `MenuSettings` (unknown keys kept, never overwritten when unreadable); the deployed JSON is the Spec `MenuDef` and the INI the Spec `writeDefaultModIni` (`src/shared/menu.ts`); the INI is created if absent and never overwritten or retired; the menu SWF path is the one constant `menuSwfPath` (O2, unverified in game); the generated menu class `mods.<modId>.<Swf>Menu` starts the graphs after the runtime bridge is ready (S4.2 retry rule); the mock `_root.inkwell` exists in the preview SWF only (`docs/menus.md`). Saved variables (S5.4: `getSaved` in `init()` with a type check, `setSaved` after nodes with `extra.writesVariable`) and the list component (a role `list` frame becomes `mods.<modId>.InkwellList`, generated in `src/main/swf/listAs2.ts`) are compiler features; the runtime-only nodes are mocked in the preview (`docs/menus.md`, Runtime-only nodes in Ruffle). `runtime-required` follows the node definition flag only. **Runtime check (Phase 7, `docs/menus.md`):** every customMenu mod deploys `<modId>_RuntimeCheck.esp` (ESL, NO master, a quest with a player alias) + `Scripts/<modId>_RuntimeCheck.pex` + the `.psc` (one script on the alias asks `SKSE.GetPluginVersion("Inkwell")` and shows the Spec `RUNTIME_MESSAGES`); it needs the user's Papyrus compiler, is always in Package Mod / Vortex (without a compiler: gate ERROR `runtime-check-missing`; a folder deploy warns), is separate from the widget plugin (`<modId>.esp`, SkyUI master), and its minimum is `projectMinRuntime` (`src/shared/runtimeFeatures.ts`, same value in the menu JSON, the script and the dialog). The preview has a UI Scale control (`preview/uiScale.tsx`, mock callback `inkwellUiScale`); the glue applies `uiScale`/`offsetX`/`offsetY` to `_root`. Menu names and paths that are Windows device names (CON, NUL, COM1) are refused. Nothing of this ran in game.
- **Dev mode token**: lives in the editor's user settings per project (`devLinks`), is never in a project, git, log, UI state, toast or deploy dialog (only masked `ab12...ef90`); Package Mod and the Vortex zip never contain dev mode, the token or dev hooks; dev hooks exist only in the `dev: true` build of a custom menu (`docs/dev-mode.md`). The editor connects without an Origin header to `127.0.0.1` only.
- **Debugging in the preview is Ruffle** (the game's live trace and watch are `docs/dev-mode.md`; `docs/debugging.md`): the AS2 split view, Play panel (ExternalInterface bridge in the preview SWF), mock data delivery, trace panel (Ruffle's console output), pin value badges. A graph save rebuilds the preview; mock data never does. Preview-only code (`preview: true` in codegen: pin traces, mock hooks, the bridge) never goes into the game SWF. The Ruffle source says "Ruffle preview, not the game".
- **Generated AS2 is readable and source-mapped** to node IDs (`src/main/codegen`, `docs/codegen.md`; a graph class is not declared `dynamic` because FFDec's AS2 compiler cannot parse it). Classes are namespaced `mods.<modId>.*`; translation keys `$Inkwell_<Mod>_…`.
- **Errors never crash a menu:** generated code coerces node outputs to pin defaults and wraps each event handler in `try/catch` that logs the node ID.
- **Pure nodes are cached per dependency scope** (per event run, or per loop iteration when they depend on the loop element); volatile reads (Get Variable, Get Text, and anything fed by them) are never cached. Tests in `codegen.test.ts`.
- **The FFDec wrapper fails a build when an AS2 script does not parse.** Rebuild the jar (`yarn build:wrapper`) after pulling; the template test (`templates.integration.test.ts`) compiles every core template with it.
- **No JavaScript from node packs runs in the editor.** Packs are declarative; load them as data.
- **Author-owned config is JSON; end-user-owned config is INI.** The editor generates both, plus a commented default INI per mod.
- **Local servers need origin checks and a credential.** Runtime debug connection: a token (64 hex digits, kept in `Inkwell.ini`, never in the project; S6). Figma bridge: no token; an approved plugin secret (protocol 4; `selectNode` is protocol 5 and goes only to approved connected sockets): an unknown secret gets `pending` and the user's Allow / Deny prompt, a pending socket can send nothing (closed after 60 s), one prompt at a time and one per minute, a denied secret is refused for the session, only the SHA-256 of an approved secret is stored (user settings, never the project, never the secret), constant-time compare (`src/main/sync/figmaTrust.ts`, `docs/sync-server.md`). Bind to localhost only.
- **Never ship or export Bethesda's vanilla SWFs.** Extract from the user's install into a per-game-version cache; git-ignore it; refuse to export unmodified vanilla files.
- **Images follow the project's `imageMode`:** `embedded` (default) compiles bitmaps into the SWF; `dds` loads `img://textures/Inkwell/<modId>/<hash>.dds` at runtime and deploys the DDS files. The preview always embeds (Ruffle has no `img://`). Asset hashes become file names: validate them (`AssetHash`). Which mode works in Skyrim's GFx is unverified (`docs/images.md`).
- **Never touch `fontconfig.txt`;** embed custom fonts in the mod's own SWF.
- **Extracted game fonts stay on the user's machine:** the font tool installs them per user only (never HKLM or `C:\Windows\Fonts`), never overwrites fonts it did not install, and nothing extracted is ever written into a project, build, deploy or the repo.
- **FFDec is user-installed** and driven as a separate process. Never bundle it. A cold FFDec run takes about 2.4 s, so builds go through a resident wrapper (a separate component on `ffdec_lib.jar`, LGPL, pinned to an FFDec version) that takes jobs over stdin/stdout.
- **Text compiles to `DefineEditText` with a font id and outlines**, importing the alias font from `gfxfontlib.swf` (`ImportAssets2`), as vanilla menus do. Never `fontClass` or device fonts: they draw nothing in Skyrim.
- **The Ruffle preview uses its own SWF** (`<name>.preview.swf`: text with embedded glyph outlines of the preview font (device font only without font bytes), fonts and glyph embedding in `docs/preview-fonts.md`; no `ImportAssets2`), because Ruffle cannot load `gfxfontlib.swf`. The game SWF never uses it. UI panels take no props and import no other panel; layouts are data (`docs/ui-panels.md`). Behaviour mode: the graph owns the centre column and the preview is a small fixed-size slot (`fixed` layout node, no splitter, stored sizes ignored) above the Inspector; the preview goes compact there (`docs/ui-shell.md`, Modes).
- **Generated AS2 stays at Flash 8 level.** `try/catch` works, but there is no `Error` class (throw strings or plain objects), and AS2 runtime `flash.filters` is unavailable.
- **The Papyrus compiler is user-pointed, not bundled.** Header stubs are written from scratch and must match real declarations (full properties vs `auto`); wrong stubs compile silently to broken code.
- **SkyUI widgets need two scripts** (the widget and an empty `...Instance` that extends it), the SWF in `Interface/exported/widgets/<mod>/`, and a root clip named `widget`. Never bundle SkyUI files (no license).
- **Measure every build stage** (sync, codegen, FFDec, preview) and keep the preview behind the pluggable preview interface; Ruffle is the only 1.0 implementation.
- **Skyrim translation files** use full language names and the game's expected encoding; cover the exporter with tests.
- **Editor UI is English only in 1.0**, but all UI strings live in one module.
