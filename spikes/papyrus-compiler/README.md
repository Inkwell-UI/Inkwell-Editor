# Spike 7: Papyrus compiler (russo-2025) with from-scratch header stubs

Status: **compile and structural comparison done. Round 1 in-game: pex loads and runs, but SkyUI refused the widget (script not derived). Round 2 (base + Instance fix) UNVERIFIED, awaiting human test.**

## Question
Can russo-2025's `papyrus-compiler` (MIT) compile a generated SkyUI-style HUD widget script using ONLY minimal header stubs written from scratch (no Creation Kit files, no Bethesda `.psc`, no SkyUI source copied)?

## Answer
Yes, with one trap. It compiles in about 3 ms and the pex is equivalent to the official compiler's output by reading. The trap: **stubs must declare `auto` vs full properties exactly as the real script does** (see "Stub fidelity").

## Tool
`papyrus-compiler-windows.zip` from release `2026.03.15` ("V 0.0.4"); `papyrus version`: v0.0.4, commit `456458c` (tag sha `456458cafcd9e864598f8d9a5eaa77d82bdb52e6`). Zip SHA-256 `67B44C77D00A5CDA986BEC6AF5C228A56ABE6EC1FADCB4CFEA5C858E6941140E`. GitHub metadata says MIT; **the zip contains no LICENSE file**, and it bundles an `Original Compiler` folder of Bethesda CK binaries, which we must not redistribute. Extracted outside the repo (scratchpad `russo\`) and run by explicit path only. No source build was needed.

## What is here
- `stubs/*.psc`: original stubs, each marked "original stub, not a Bethesda/SkyUI file": `ScriptObject, Form, Quest, Debug, Utility, UI, StringUtil, SKI_QuestBase, SKI_WidgetBase`. Declarations only, written from public API knowledge.
- `src/Inkwell_SpikeWidgetInstance.psc`: empty `extends Inkwell_SpikeWidget`; this is the script the quest carries.
- `src/Inkwell_SpikeWidget.psc`: generated-style widget (extends `SKI_WidgetBase`, `GetWidgetSource` returns `Inkwell/InkwellSpikeWidget.swf`, position set in `OnWidgetReset`, `Debug.Trace` + `Debug.Notification`, header "generated by Inkwell (spike)").
- `compile.ps1`: wrapper for the russo command.
- `swf/`: widget SWF built from sources: `gen-widget.mjs` (skeleton generator derived from the ffdec spike's `gen-swf.mjs`), `src/shapes/1.svg` (red 200x40 rect), `src/as2/frame_1/DoAction.as`, `build.ps1`. Dynamic text `INKWELL WIDGET`. The root timeline implements the calls SkyUI makes (`setHAnchor/VAnchor/PositionX/PositionY/Alpha/Modes/ClientInfo`) plus `setLabel`. Run `swf/build.ps1 [-Deploy]` (Node + user-installed FFDec).
- `plugin/make_esl.py` -> `plugin/InkwellSpikes.esp`: tiny writer for an ESL-flagged plugin (master SkyUI_SE.esp, start-game-enabled quest `InkwellSpikeQuest` with the script attached via VMAD). Built from public UESP record layouts; **never opened in xEdit, CK or the game**.

## Commands
```
papyrus.exe compile -nocache -h <repo>\spikes\papyrus-compiler\stubs -i <repo>\spikes\papyrus-compiler\src -o <out>
```
`-h` = header dir (analysed, not compiled); `-nocache` forces a rebuild. Output `Inkwell_SpikeWidget.pex` (1273 bytes) and `Inkwell_SpikeWidgetInstance.pex` (486 bytes), no errors. Official: 1456 and 606 bytes, 0 errors, 0 warnings (compile each script by name).

Official build (scratch only, nothing copied into the repo):
```
PapyrusCompiler.exe Inkwell_SpikeWidget.psc -f=TESV_Papyrus_Flags.flg -i="<src>;<scratch overlay>;<CK Data\Source\Scripts>;<skyui-community\source\scripts>" -o=<out>
```
Run with a cwd holding the flags file and the .psc; the script's own dir must be in `-i`. 1456 bytes, 0 errors, 0 warnings.

## What generated scripts use (stubbing list)
- Types: `Form` (+ `ScriptObject`), `Quest`, `SKI_QuestBase`, `SKI_WidgetBase`.
- `SKI_WidgetBase`: properties `WidgetName HAnchor VAnchor X Y Alpha Modes WidgetID Ready WidgetRoot`; events `OnWidgetInit OnWidgetLoad OnWidgetReset`; functions `GetWidgetSource GetWidgetType GetDimensions TweenTo TweenToX TweenToY FadeTo`; `Parent.OnWidgetReset()`.
- `Debug.Trace/Notification/MessageBox`; SKSE `UI.Invoke{Bool,Int,Float,String,FloatA,StringA}`, `Set*`, `Get*`, `IsMenuOpen`; `Utility.Wait/RandomFloat/GetCurrentRealTime`; SKSE `StringUtil.GetLength/Substring`; SKSE `Form.RegisterForModEvent/SendModEvent/UnregisterForModEvent`.
- Not needed for this widget: Actor, ObjectReference, Game, Spell. Add stubs per feature as codegen grows.

## Stub fidelity (important)
The first stub declared `HAnchor`, `X`, `Y`, `Alpha` as `auto`. russo compiled without error but emitted **direct field stores** (`assign ::HAnchor_var`) instead of `propset`. The real SKI_WidgetBase has get/set bodies for them, so that pex would write a variable that does not exist in-game. Declaring them as full properties in the stub fixed it (`propset`, same as official). The compiler cannot detect a stub that lies. For Inkwell: generate stubs from the interface actually installed, or pin and test them; never guess auto vs full.

## Comparison (russo vs official, both decoded with `papyrus read`)
The official build used the real SkyUI sources (community clone, read-only) and the user's CK sources, plus a scratch overlay for SKSE pieces the CK sources lack (`UI.psc` and `StringUtil.psc` = our stubs; `Form.psc` = CK's plus 5 hand-added SKSE natives). So the official compiler also cannot run on CK sources alone: SKSE's `UI`, `StringUtil` and ModEvent functions are not in CK.
- Byte-identical: no (1273 vs 1456 bytes; timestamps differ regardless).
- Same: magic 0xfa57c0de, v3.2, game skyrim; object name; parent `SKI_WidgetBase`; 0 variables/properties; 1 state; the same 6 functions (order differs); the same operations (propset HAnchor/VAnchor/X/Y/Alpha, propget WidgetRoot/X/Y, callparent OnWidgetReset, callstatic Debug/UI, cast, strcat); same string constants.
- Different:
  - Temps: official routes each constant through a `::tempN` local before `propset`; russo passes the literal (`propset X self 1100.0`). Instruction counts: OnWidgetReset 16 vs 19, OnWidgetInit 4 vs 6. Equivalent by reading.
  - Static call target case: official `debug`/`ui`, russo `Debug`/`UI` (Papyrus is case-insensitive).
  - russo drops the object doc string, orders the string table differently, writes a different object `size` field (0x1c2 vs 0x1e9) and a constant `modification_time`.
- Unknown: whether the game's VM accepts russo's pex. Only the in-game test answers it.

## Findings from the in-game round 1 (for Inkwell codegen)
- **SWF root path:** SkyUI loads widget SWFs from `Interface\exported\widgets\`, so `GetWidgetSource` returns a path relative to that (`Inkwell/InkwellSpikeWidget.swf`) and the file lives at `Interface\exported\widgets\Inkwell\InkwellSpikeWidget.swf`. `swf/build.ps1 -Deploy` now deploys there.
- **Base + Instance:** the pex ran, but SkyUI showed "[...] must extend a base script type" and never registered the widget. `SKI_WidgetBase.IsExtending()` returns false when the attached script's name equals `GetWidgetType()`. SkyUI's own widgets are a base script plus an empty derived `...Instance` script attached to the quest. Generated widgets therefore need two scripts (`Foo` with the logic, `FooInstance extends Foo` attached to the quest), or the ESP must set the `RequireExtend` property to false on the single script (stub has `RequireExtend auto` and `IsExtending`).
- **Notification timing:** `Debug.Notification("... ready")` in `OnWidgetReset` only fires after the widget manager registers the widget; `OnWidgetInit` and the `INITIALIZED` trace fire earlier regardless.

## Result
Compile: PASS. Structural equivalence: PASS by inspection. In-game: round 1 ran but was rejected by SkyUI (fixed above); round 2 UNVERIFIED.

## Risks / not checked
- The hand-written esp (VMAD quest-fragment trailer) may be malformed; not validated in xEdit or CK.
- The SWF's AS2 relies on unqualified `place()` using the timeline as `this`; it omits SkyUI's HUD-metrics scaling and `HudElements` registration, so it may mis-position or ignore HUD modes.
- SkyUI's interface was read from the community clone, which may differ from the installed 5.2 SE.
- The russo release ships no LICENSE file.

## Findings from the in-game round 2 (widget SWF contract)
- SkyUI's `WidgetLoader.onLoadInit` fails with `WidgetInitFailure` unless the loaded SWF's root (the holder) has a child clip instance named `widget`. It then calls `widget.setHudMetrics(m)`, `widget.setRootPath(p)` and (via the holder) `widget.onModeChange(mode)`. `SKI_WidgetBase` builds `WidgetRoot` = `_root.WidgetContainer.<id>.widget`, so every `UI.Invoke*(WidgetRoot + ".setX")` (setLabel, setHAnchor, setPositionX, ...) targets methods on that `widget` clip, not the SWF root.
- `gen-widget.mjs` now emits a DefineSprite (shape + dynamic TextField `label`) placed at root as `widget`; `src/as2/frame_1/DoAction.as` attaches the methods to it. `skse.Log` is used only behind `typeof` + try/catch.
- Widget folder is `Interface\exported\widgets\` (not `exported\`); `GetWidgetSource` stays `Inkwell/InkwellSpikeWidget.swf`. Verified with `ffdec -swf2xml`: root PlaceObject2 has `name="widget"`. Not re-tested in game.
- **Widget text encoding (variant A):** the old `fontClass` / device-font encoding of the `label` field draws nothing in Skyrim's GFx (ffdec spike). `gen-widget.mjs` now emits the in-game-proven variant A: `ImportAssets2` of `$EverywhereMediumFont` from `gfxfontlib.swf` into local id 3, and `DefineEditText fontId=3 hasFontClass=false useOutlines=true`. Verified with `ffdec -swf2xml`; `widget`/`label` clip contract unchanged. Not re-tested in game: expect a red bar top-right reading `INKWELL WIDGET`.
